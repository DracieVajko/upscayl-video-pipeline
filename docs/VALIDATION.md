ruff on Ubuntu, the V2 PowerShell harness, PSScriptAnalyzer and the cross-version

## GPU-dependent tests (executed on 2026-11-12)

- `doctor` exits `0` on this host. FFmpeg/ffprobe, NVENC and AMF encoders,
  `zscale`, the work directory, Upscayl 2.15.0, 11 models and the smoke encode
  all pass.
- A real end-to-end run on `Test3_SecurityCamera_Dog.mp4` (a 1-second window,
  60 frames):
  - split: 60 frames at 960×720, CPU decode (0.30 s vs 0.68 s GPU);
  - upscale: 60/60 frames at 2× with `upscayl-lite-4x`, 2.58 frames/s,
    24.2 s wall time, real NVIDIA GPU;
  - assemble: 1920×1440 H.264, 60 frames, 1.000 s, 0.5 MB output.
- The host has an AMD Radeon integrated GPU and an NVIDIA GeForce RTX 3060
  Laptop GPU. The default Vulkan ICD on this host is the AMD one and fails with
  `vkEnumeratePhysicalDevices failed -3`; forcing the NVIDIA ICD works.
  `--icd auto` now finds the working ICD automatically (the previous
  implementation searched with backslashes, which `glob` treats as escapes and
  never matched). The fix is covered by
  `tests/test_upscayl_discovery.py::TestIcdDiscovery`.

## Limitations carried over

- VFR Matroska duration: packet-count duration is preferred for CFR output. A VFR
  source whose container duration differs materially from frames/fps can still hit
  the output-duration tolerance; no VFR fixture is in the matrix.
- `job.txt` stores native paths, so a job is not portable between operating
  systems by design.
- The V2 bash runtime's `model-test` command is not implemented.
